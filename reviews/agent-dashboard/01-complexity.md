# Architecture complexity review

| severity | area | finding | recommendation |
|---|---|---|---|
| high | configuration ownership | The dashboard port is owned by `bin/cohort-init` (`18`, `44-56`), `bin/cohort-dashboard` (`27`, `38-53`), and the systemd command in `install.sh:111`, whose explicit `--port 6283` always overrides the config file. | Make the config file the sole port authority by removing `--port 6283` from the unit and move global dashboard configuration out of per-project `cohort-init`. |
| med | status normalization | Worktree status is classified once with `new`/`noupstream`/`idle` in `bin/cohort-dashboard-prep:438-449` and again with a different vocabulary in `bin/cohort-dashboard-pr:186-212`. | Move display-status derivation to one normalization step after optional PR enrichment and let prep emit only raw git facts. |
| med | row ordering | Urgency and PR ordering are implemented in both Python (`bin/cohort-dashboard-pr:133-183`) and JavaScript (`bin/cohort-dashboard:220-268`), requiring two implementations to remain identical. | Apply ordering once in the server after either full or `no_gh` collection, then delete the PR-stage and browser copies. |
| med | orphan pipeline | `orphan_branches` admits every local branch without a worktree (`bin/cohort-dashboard-prep:269-292`), but the UI discards tracked unmerged entries at `bin/cohort-dashboard:360-362` after they have been classified, enriched, and sorted. | Exclude tracked unmerged branches once during prep so invisible rows do not travel through the rest of the pipeline. |
| med | metadata derivation | The same ISO-date parsing and `days_since_last_commit` calculation appears three times in `bin/cohort-dashboard-prep:355-364`, `427-436`, and `459-468`. | Extract a `days_since_commit(when)` helper and use it for remote-only, worktree, and orphan entries. |
| med | rendering | Orphan and remote-only row generation and table sections are near-duplicates in `bin/cohort-dashboard:380-414`, differing mainly in fallback labels and `on_remote` defaults. | Introduce one branch-without-worktree row renderer and one section renderer parameterized by title and fallback status. |
| low | dead schema | `host_of_remote` and the emitted `repo.host` field (`bin/cohort-dashboard-prep:153-159`, `382`) have no consumer anywhere in the repository beyond schema documentation. | Delete the function and field, and remove `host` from `docs/dashboard-design.md`. |
| low | PR payload | `enrich` writes nine entry-level PR fields that the repository never reads (`bin/cohort-dashboard-pr:120`, `123-130`), which also keeps unused `baseRefName`, `reviewDecision`, and `headRefOid` in the `gh` request at `95-96`. | After confirming the JSON endpoint has no external compatibility promise, remove the unused enrichment fields and stop requesting their source fields. |
| low | installation flow | The root and passwordless-sudo branches in `install.sh:120-135` duplicate unit writing, daemon reload, enablement, and success output. | Select an elevation command once and run one shared installation block, retaining the no-privilege fallback separately. |

**Bottom line:** The current three-stage shape is defensible, but configuration, normalization, ordering, and rendering each have more than one owner; reducing those duplicated ownership points is the safest path to lower complexity without a rewrite.
